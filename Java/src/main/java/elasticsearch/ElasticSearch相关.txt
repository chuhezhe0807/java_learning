Elasticsearch 是一个分布式、RESTful 风格的搜索和数据分析引擎，同时是可扩展的数据存储和矢量数据库，能够应对日益增多的各种用例。
    RESTful REST全称是Representational State Transfer，中文意思是表述性状态转移。REST指的是一组架构约束条件和原则（接口设计规范）。
    特征：
        以资源为基础 ：资源可以是一个图片、音乐、一个XML格式、HTML格式或者JSON格式等网络上的一个实体，
            除了一些二进制的资源外普通的文本资源更多以JSON为载体、面向用户的一组数据(通常从数据库中查询而得到)。
        统一接口：对资源的操作包括获取、创建、修改和删除，这些操作正好对应HTTP协议提供的GET、POST、PUT和DELETE方法。换言而知，
            使用RESTful风格的接口但从接口上你可能只能定位其资源，但是无法知晓它具体进行了什么操作，
            需要具体了解其发生了什么操作动作要从其HTTP请求方法类型上进行判断。
        URI指向资源：URI = Universal Resource Identifier 统一资源标志符，用来标识抽象或物理资源的一个紧凑字符串。
        无状态：服务器不能保存客户端的信息， 每一次从客户端发送的请求中，要包含所有必须的状态信息，会话信息由客户端保存，
            服务器端根据这些状态信息来处理请求。

    Elasticsearch 是面向文档的型数据库，一条数据在这里就是一个文档。

    倒排索引

    正排（正向）索引：数据库中的加在列上的index(索引)称之为正排索引
    使用一个文章相关的数据库做演示说明：
        id          content
        ----------------------
        1001        my name is zhang san
        1002        my name is li si

    上面数据库中的id就为正向索引，可以通过id去查询到具体的文章内容（id列设置索引，文件id关联文件内容）
    但是如果是查询包含给定字符的文章的内容，比如查询文章内容中包含name的文章，正排索引还是需要遍历所有的文章，性能开销很大。
    这时候可以换一种索引方式。以keyword与文章id关联(倒排索引)

        keyword         id
        -----------------------
        name            1001,1002
        zhang           1001

    部署环境
        单机 & 集群
            单台机器负载能力往往有限，不如集群
            单台机器存储容量有限
            单服务器容易出现单点故障，如法实现高可用
            单服务的并发处理能力有限
        配置服务器集群时，大于等于两个节点就可以看作是集群了，一般集群节点数量都是3个以上

        一个集群就是有一个或多个服务器节点组织在一起，共同持有整个的数据，并一起提供索引和搜索功能。

        /// elasticsearch.yml
        ...
        transport.tcp.port: 9302                    // 内部通信端口
        discovery.seed_hosts: ["localhost:9301"]    // 以下内容第一台机器不用配置，后续需要配置。 第二台机器找第一台机器的内部通讯端口号
        discovery.zen.fd.ping_timeout: 1m
        discovery.zen.fd.ping_retries: 5

        linux环境部署集群时需要注意
            1、关闭linux环境的防火墙，防止服务启动后出现linux本机可以访问，但是外部无法访问的问题
            2、vim config/elasticsearch.yml 时需要注意集群名称必须一致，节点名称必须不一致
            3、config/elasticsearch.yml 中需要配置内部通讯端口 transport.tcp.port: 9300和 discovery.seed_hosts，防止集群启动后，查询不到其他节点
            4、复制es到其他linux机器时，es安装目下的data和log文件需要清空，防止data/nodes中包含有其他节点的信息，导致启动报错
